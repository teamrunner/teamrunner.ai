Team engineering for AI agents

Build a team of AI agents from text files. Experiment. Improve.

Each agent is a text file of plain instructions. A team is a folder. One more file, the chair, says who speaks when. TeamRunner runs the team, keeps every word, decision and cost, and lets you change one line and run it again.

Install in two commands See it run ↓

Mac, Windows and Linux. OpenAI, Anthropic, Gemini, OpenRouter, or free local models through Ollama. No code.

Example · multi_agent_debate

Five text files → a running team

Two debaters argue a topic for three rounds, then a judge decides. The whole flow is two lines of chair.md. Rehearse it for free, watch a real run we recorded on Claude Haiku 5.5, then add a fact checker: one new file and a few new lines in chair.md, and the flow redraws.

    Recorded run

    runs

    Now it’s an experiment. Does fact-checking change who wins, or only make the debate longer and costlier? In our six recorded runs on the motion “Splitting AI work into clear roles makes it safer and easier to audit and improve than one prompt doing it all”, for won two of three plain debates but only one of three checked ones; the replay shows one of each. The fact checker never failed a speech, and the checked debates cost about twice as much. Three runs each is too few to call it. Would your model agree? Run each version a few times and compare: that is tutorial step 8, on a real question.
    This fact checker works only from what its model remembers. To let it check sources, give it the web.

    The experiment · hiring_committee

    Every fact the committee needs is in the room. Does it find them?

    Three AI agents are hiring for a food bank. Each holds two facts the others don’t, and only with all six on the table is Blake, not Avery, the right choice.

    Human groups mostly miss facts like these (Stasser and Titus, 1985), and a well-known fix is to have everyone share what they know before anyone gives an opinion.

    In TeamRunner that fix is one line of chair.md: swap it, run both versions, and see whether the agents do better.

    The whole case: the packet, the private facts and the commands →

    chair.mdopen discussion → share first
    # How the meeting is run. This is the line the experiment changes.
    - meeting(*3) -> clerk:record
    + # meeting(*3) -> clerk:record
    - # chen:share_facts -> diaz:share_facts -> okafor:share_facts -> meeting(*2) -> clerk:record
    + chen:share_facts -> diaz:share_facts -> okafor:share_facts -> meeting(*2) -> clerk:record
    meeting = chen -> diaz -> okafor
    Red is the old line, green the new one: this view of a change is called a diff. A line starting with # is a note for people, and is not run.

    Why a team?

    A team isn’t automatically better than one agent. So test it.

    Studies find the gains over a single agent are often small (Cemri et al., 2025). TeamRunner treats a team’s structure as a hypothesis: change a line, rehearse for free, run both versions and compare. These are the ten reasons a team can help, each borrowed from how organizations work.

    1. 01One job per agentA job description, not “other duties as assigned”
    2. 02Smaller contexts, steadier behaviourA briefing, not the whole archive
    3. 03The right model for each jobYou don’t staff every desk with a senior partner
    4. 04Costs you can see, and boundA budget line for each department
    5. 05Guardrails where the tools areThe tool crib, not a power drill on every desk
    6. 06A flow you can read, control and changeThe meeting rules, written down
    7. 07Checks and balancesSeparation of duties: the writer isn’t the editor
    8. 08Information where it belongsNeed to know
    9. 09Every step on the recordMinutes for every meeting
    10. 10Improve by experiment, not by hunchPilot it, then make it policy

    Two ways to work

    In your browser or in a terminal. Same files either way.

    in your terminalfree, no key
    teamrunner new hello --from round_robin
teamrunner run hello --rehearse
teamrunner runs hello

    Both work on the same folder of plain text files, so you can switch between them at any time. The tutorial shows every step both ways.
