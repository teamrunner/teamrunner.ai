The experimentation platform for agent organizations

Run a team of AI agents from text files. Change one line. Run it again.

An agent is a Markdown file, a team is a folder, and the org chart is the directory tree. No Python and no framework to learn. Edit the prose, run one command, and every prompt, reply and cost is kept.

Mac, Windows and Linux. Works with OpenAI, Anthropic and free local models through Ollama.

Why it is needed

Teams of agents are a new laboratory for studying organizations. It has been built for programmers.

Built for the people who study organizations

Management scientists and behavioural economists know how structure changes a team's output. They shouldn't have to write hundreds of lines of orchestration code to ask their first question.

Structure is a one-line change

Who reports to whom, who sees which facts, who decides. Each is a value in a file, and anything in a file can be varied in an experiment.

One run is an anecdote

Most published multi-agent results come from a single run. TeamRunner seeds what it controls, replicates what the model makes random, and records everything.

A study you can send someone

A team folder is a replication package. Zip it, put it in git, cite it in a methods section. Anyone can rerun it with the exact version you used.

Install

Running in five minutes, even without Python

The installer, uv, fetches the right version of Python on its own. You need a terminal and an API key, or Ollama for free local models.

  1. Open Terminal (press ⌘ Space, type “Terminal”) and install uv:curl -LsSf https://astral.sh/uv/install.sh | sh
  2. Close Terminal, open it again, then install TeamRunner:uv tool install teamrunner
  3. Check that it works:teamrunner new hello --from round_robin
  1. Open PowerShell from the Start menu and install uv:powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  2. Close PowerShell, open it again, then install TeamRunner:uv tool install teamrunner
  3. Check that it works:teamrunner new hello --from round_robin
  1. In a terminal, install uv:curl -LsSf https://astral.sh/uv/install.sh | sh
  2. Open a new terminal, then install TeamRunner:uv tool install teamrunner
  3. Check that it works:teamrunner new hello --from round_robin
  1. Python 3.10 or later:pip install teamrunner

Then put your key in ~/.teamrunner/.env, a file in your home folder that is never inside a team. TeamRunner offers to put it there the first time it needs one.

Tutorial

Your first team, in ten minutes

Build a three-agent debate from four text files, then give it rounds, a fact checker and the web. Every step ends with a rehearsal, a run with no model at all: free, and no key needed, so you can follow along before you have one.

Start the tutorial

seven stepsno code
  1. Make a team
    One command, and one file that says what the team does.
  2. Write three agents
    An advocate, a critic and a judge, each a Markdown file.
  3. Check it, then rehearse it
    Catch mistakes before a single token is spent.
  4. Run it for real
    With your key, for a fraction of a cent.
  5. Give it rounds
    A chair: the meeting's script, in two lines.
  6. Add a fact checker
    A speech that fails goes back, at most twice.
  7. Give the team the web
    Through a toolkeeper, on terms you set.

Concepts

Five ideas cover the whole format

An agent is a Markdown file

Settings at the top, the prompt as prose below. Edit it in any text editor.

judge.md

A folder is a team

Any folder with a team.yaml is a team. A team inside a team is a subcommittee. The file browser is the org chart.

team.yaml

Every team has a chair

Someone always decides who speaks next: a script you wrote, or members in name order. Every decision is logged.

chair.md

Tools sit behind a toolkeeper

Like a factory's tool crib: one member holds the web search or the code sandbox and decides who may use it, on what terms.

web.md

Experiments are overlays 0.2

An experiment file sits outside the team and patches it. The team itself stays clean and runnable.

experiment.yaml

Concepts · what every run keeps

A run folder is a full record, on your own disk

Plain files you can open, diff and query. No dashboard you have to log in to, and no agent can read or change the log.

Every prompt and every reply
Exactly what each agent could read, what it said, which model answered, tokens, cost and time.
Every decision about who acts next
Who made it and why. There are no hidden if-statements.
Every tool call
Who asked, whether the toolkeeper said yes, and what came back. Web search results are read but not kept, as Brave’s terms require.

A question from the study of groups

When the key facts are spread across a committee, does it pick the best candidate?

In 1985 Stasser and Titus showed that human groups mostly discuss what they all already know, and so miss the facts that would change their decision. It is one of the most replicated findings about how groups decide. With TeamRunner you can ask whether a committee of AI agents does the same, and what fixes it.

The task

Three members, three candidates, and facts no one person has

The committee is hiring a Director of Operations for a food bank. Everyone has read the same packet, which makes Avery look best. Each member also holds two facts the others don't.

Alone, each member would still choose Avery. With all six facts on the table, Blake is the clear choice.

The change

Change how the meeting is run, in one line

A well-known fix from the research is to have everyone report what they know before anyone gives an opinion. In TeamRunner the way a meeting runs lives in one file, chair.md. Moving one # switches from open discussion to share-first. Nothing else changes.

chair.mdopen discussion → share first
# How the meeting is run. This is the line the experiment changes.
- meeting(*3) -> clerk:record
+ # meeting(*3) -> clerk:record
- # chen:share_facts -> diaz:share_facts -> okafor:share_facts -> meeting(*2) -> clerk:record
+ chen:share_facts -> diaz:share_facts -> okafor:share_facts -> meeting(*2) -> clerk:record
meeting = chen -> diaz -> okafor
The run

Run both versions. Then run them fifty times.

Every turn records whom each member would hire right now, so you can see when minds change and whose facts changed them. One run is an anecdote, because models are random. With experiments, one file describes both versions and the number of runs, and you get one CSV for R, Stata or pandas.

today0.0.2
teamrunner new committee \
  --from hiring_committee
teamrunner run committee
teamrunner runs

All six examples

Start from the one closest to what you want

Each adds something the one before it doesn’t have. Copy one by name, and it is yours to change: teamrunner new my_team --from fact_checked

round_robin

The simplest team: three members and no chair, one turn each in name order, and a typed verdict.

multi_agent_debate

A chair: the debate as a script, with a repeated block of rounds.

hiring_committee

The committee above: facts only one member knows, kept in that member’s own file.

orchestrators_lite

Five engineers review code against planted bugs, sharing one model profile.

fact_checked

The debate with a fact checker, a web search on different terms for different members, and a Python sandbox.

reference_check

Checks every reference in a paper: that it exists, that its details are right, and that it says what the citing sentence claims.
