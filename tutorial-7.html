So far everyone knows the same things. The example hiring_committee is a committee choosing a Director of Operations, where each member also knows two facts the others don't. Copy it into a team called committee:

+ Team, committee, from hiring_committee.

teamrunner new committee --from hiring_committee

This committee is a bigger job than the debate: ten turns a meeting, with longer instructions, and step 8 runs it ten times. That is more than the demo model is for, so from here the tutorial uses a model of your own: Gemma 4, through OpenRouter, one key for many providers' models. The example runs on Claude through Anthropic; change the model its members share. It is a model profile, models/member.yaml, named once in team.yaml:

committee/models/member.yamlchange this line
- name: anthropic/claude-haiku-5-5
+ name: openrouter/google/gemma-4-31b-it

Open models/member.yaml in the committee's files, change the line, and Save.

A model of your own needs an API key: a code from the provider that lets TeamRunner use it, billed by the provider. Make an account at OpenRouter, add a few dollars of credit and create a key. TeamRunner keeps keys in one file, ~/.teamrunner/.env: a file called .env in a folder called .teamrunner in your home folder. It is never inside a team, because team folders get shared and a key would go with them. Without it, a real run stops before anything is spent and says which key it needs.

Choose Set up keys, pick OPENROUTER_API_KEY, paste the key into New key and choose Save key. The page writes it to that file and never shows it again; Validate checks that it works.

Put your key in it:

~/.teamrunner/.envin your home folder
OPENROUTER_API_KEY=sk-or-...

Without it, a real run stops and says so:

without a key
✗ the run cannot start:
  OPENROUTER_API_KEY   chen, clerk, diaz and okafor use openrouter/google/gemma-4-31b-it,
                       which needs OPENROUTER_API_KEY; not found in ~/.teamrunner/.env,
                       your shell or the package
                       add `OPENROUTER_API_KEY=…` to ~/.teamrunner/.env

What everyone has read, the application packet, is in team.yaml. What only one member knows is written into that member's own file:

committee/chen.mdpart of it
You also sat in on the reference calls, and your notes say:

- Asked whether they would hire Avery again, Avery's former manager
  said only that it was company policy not to comment.
- Blake's former manager said Blake was the best operations person
  they had worked with.

The others have not seen your notes.

The others learn Chen's notes only if Chen says them in the meeting. Each member answers preferred every turn, whom they would hire right now, so you can see when minds change; the clerk records the decision. Rehearse it, then run it for real.

Run… twice: once rehearsed, once Run with models. Run history shows each run's decision.

teamrunner run committee --rehearse teamrunner run committee teamrunner runs committee

The packet makes Avery look best; the six private facts together make Blake the clear choice. In 1985 Stasser and Titus found that human groups mostly discuss what they all already know, and pick Avery. What did your committee do?
