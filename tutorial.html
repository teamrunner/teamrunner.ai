Tutorial

Your first team, in ten minutes

You will build a debate between two AI agents with a judge, run it, and then give it rounds, a fact checker and the web. No code: every step is a text file or one command.

Before you start, install TeamRunner. Every step ends with a rehearsal, a run with no model at all: free, and no key needed. Only step 4 calls a real model, and that is the step that needs a key.

  1. Make a team
  2. Write three agents
  3. Check it, then rehearse it
  4. Run it for real
  5. Give it rounds
  6. Add a fact checker
  7. Give the team the web

Step 1Make a team

Open a terminal in any folder and make a team called debate:

teamrunner new debate

This makes a folder, debate, with one file in it that matters: team.yaml. A folder is a team when it holds a team.yaml. Open it in any text editor and replace what is there with this:

debate/team.yaml
name: debate
description: Two debaters argue a topic; a judge decides

default_model: openai/gpt-6-luna

message_goes_to: topic

default_inputs:
  topic: "Remote work makes teams more productive"

default_model is the model every agent in the team runs on, unless an agent names its own. default_inputs is what the team argues about unless you say otherwise. message_goes_to says that a message you give on the command line becomes the topic.

Step 2Write three agents

An agent is a Markdown file in the team's folder: settings between the --- lines at the top, and below them the agent's instructions, in plain words. Make these three files in debate.

debate/advocate.md
---
description: Argues in favor of the topic
---
You are debating in favor of this topic:

> {{topic}}

Each round, make your strongest remaining argument in one short
paragraph. From round two onward, also rebut your opponent's most
recent point before adding your own. Be persuasive but honest.
debate/critic.md
---
description: Argues against the topic
---
You are debating against this topic:

> {{topic}}

Each round, rebut your opponent's most recent point, then make your
strongest remaining argument against the topic in one short paragraph.
Be persuasive but honest.
debate/judge.md
---
description: Decides who argued better
output:
  winner: [advocate, critic]
  reasoning: ""
---
You have watched a debate on:

> {{topic}}

Decide which side argued better — judge argument quality and logical
clarity, not your own opinion of the topic. Announce the winner and
explain your decision in one paragraph.

Three things to notice:

  • No agent names a model, so all three run on the team's default_model. An agent that should run on another adds its own line, model: …, which wins. teamrunner show debate/judge.md prints the judge as it will run, model included.
  • {{topic}} is filled in from team.yaml, or from your message.
  • output: makes the judge's verdict a fact you can count: winner is one of two names, reasoning is text. TeamRunner never guesses from free text what an agent decided.

There is no file saying who speaks when, so the members take one turn each, in alphabetical order: advocate, critic, judge. The folder listing is the running order.

Step 3Check it, then rehearse it

validate reads every file and points at any mistake, with the line and a fix, before a single token is spent:

teamrunner validate debate

A rehearsal runs the whole team with no model: each member says placeholder words, and each typed answer is picked at random from what its file allows. It costs nothing and needs no key. It shows whether the flow goes where you meant, not whether the answers are good.

Step 4Run it for real

Put your OpenAI key in TeamRunner's key file, ~/.teamrunner/.env, in your home folder and never inside a team (team folders get shared, and a key would go with them). If the key is already set in your terminal, TeamRunner offers to save it the first time.

~/.teamrunner/.envin your home folder
OPENAI_API_KEY=sk-...

Then run the debate, on its default topic or on one you give:

teamrunner run debate teamrunner run debate --message "Four-day weeks make teams more productive"

Each turn shows who spoke, what they decided, how long it took and what it cost; a run like this costs a fraction of a cent. Every run is kept in debate/runs/: everything said, every prompt, the model that answered, and the cost. To see them all, newest first:

teamrunner runs debate

Other providers work the same way: change default_model: to anthropic/… or gemini/… and put that provider's key in the same file. Free local models work too, through Ollama: ollama/llama3.2.

Step 5Give it rounds

A real debate has rounds. Who acts when is the job of the team's chair, a file called chair.md holding the meeting's script. Add it:

debate/chair.md
# Three rounds of advocate and critic, then the judge decides.

rounds(*3) -> judge

rounds = advocate -> critic

a -> b means one after the other, rounds(*3) repeats a step three times, and rounds = … says what that step is. Lines starting with # are notes for people. Now the debate runs advocate, critic three times over, then the judge.

teamrunner run debate --rehearse

To read the flow back in plain English, or as a picture in your browser:

teamrunner explain debate teamrunner explain debate --diagram

Step 6Add a fact checker

Suppose each speech should be fact-checked before it stands. A fact checker is one more agent, whose output: is a verdict:

debate/fact_checker.md
---
description: Checks the factual claims in the latest speech
output:
  verdict: [pass, fail]
  reasons: ""
---
You are a neutral fact checker in a formal debate. Examine the latest
speech for checkable factual claims and verify them by searching the
web (ask the web toolkeeper). Search only for claims you cannot confirm
from what you know; most speeches need one or two searches. Minor
exaggeration is fine; invented statistics, misattributed quotes and
false claims are not.

Set verdict to fail only if a claim is materially false, and list each
false claim with a one-line correction in reasons. Otherwise set it to
pass.

The chair decides what each verdict means. Replace chair.md with:

debate/chair.md
# Three rounds. Each speech is fact-checked; a failed speech gets two
# more tries, then the debate moves on. Then the judge decides.

rounds(*3) -> judge

rounds = advocate_turn -> critic_turn

advocate_turn = advocate -> fact_checker
                fact_checker --fail--> advocate
                fact_checker --pass,*3--> done

critic_turn = critic -> fact_checker
              fact_checker --fail--> critic
              fact_checker --pass,*3--> done

--fail--> advocate sends a failed speech back. --pass,*3--> done reads “on pass, or the third time, this turn is done”: every loop needs a limit, so a debate always ends. The fact checker's file says how to judge; the chair says what its verdict means here, which is why the same fact checker serves both sides.

teamrunner validate debate teamrunner run debate --rehearse

Mistype an option, say --puss-->, and validate stops you: “puss is not one of fact_checker's options; did you mean pass?”

Step 7Give the team the web

Agents never hold tools themselves. A tool sits with a toolkeeper, a member with no model that checks who is asking and enforces the limits, like the attendant at a tool crib. Add one for web search:

debate/web.md
---
description: The web toolkeeper — searches the web, on different terms for different members
kind: toolkeeper
tools:
  web_search_brave: {max_results: 5, calls_per_turn: 2}   # the base terms
access:
  fact_checker: {calls_per_turn: 3}   # a few claims a speech may need checking
  judge: standard                     # the base terms
---
I search the web. Send me a search query and I return the top five
results with their sources.
  • tools: names the tool and its base terms: five results, two searches a turn.
  • access: lists who may use it. The fact checker may search three times a turn; the judge gets the base terms; the debaters, not listed, argue from what they know.
  • The text below is what the members who may use it are told about it.

Nothing in the chair mentions web: during its turn the fact checker may search, up to its limit, or not at all. Every request, the toolkeeper's yes or no, and the search are logged. explain prints who may use what, on which terms:

teamrunner run debate --rehearse teamrunner explain debate

For real searches, add a Brave Search API key to the same key file as BRAVE_API_KEY. A search costs half a cent at Brave's list price, and a run's cost counts it.
