A model profile (models/<name>.yaml)

A model profile keeps a model and its settings together in one file, since the right settings depend on the model. Members name it as model: careful.yaml, and a team as default_model: careful.yaml; changing the file changes it for everyone who names it.

A first profile

In the team's folder, make models/careful.yaml:

name: openai/gpt-6-luna
params:
  reasoning_effort: high
  max_tokens: 4000

Then name it, in team.yaml for every member that names no model:

default_model: careful.yaml

or in one member's settings, model: careful.yaml. Each member that uses it runs on openai/gpt-6-luna, with a high reasoning effort and at most 4,000 tokens a reply.

Try it, spending nothing:

teamrunner validate debate --offline # checks the profile, and every line that names itteamrunner show debate/judge # the judge's model and settings, each marked "from models/careful.yaml"

A shipped example uses a profile: teamrunner new my_review --from orchestrators_lite, whose five engineers share models/engineer.yaml, named once as the team's default_model:.

The rest of this page is every detail.

Where it lives

A profile is a .yaml file directly in the models/ folder at the top of the team: debate/models/careful.yaml. Every .yaml file there is read and checked, whether or not anything names it. Files there that do not end in .yaml (a .yml, for example) are not profiles. The models/ folder is never searched for members.

The settings

One name: value line per setting. JSON is read too. A file that is not valid YAML, or that holds a list, is refused.

Any other word is refused, including model:, description: and id:: a profile has no id, and no description. spec_version: is refused as no longer used: files carry no version line.

Setting Needed What it is
name yes The one model this profile runs
params no Its settings, such as max_tokens

name:

The profile's model, written provider/name: name: anthropic/claude-haiku-5-5, name: ollama/llama3.2.

  • Needed. A profile without it, an empty file included, is refused: "name: is missing".
  • One model. A list (openai/gpt-5, openai/gpt-5-mini) is refused: a profile names one model, so to have a backup, list profiles in model: instead. A model with no provider (gpt-5) and another profile (other.yaml) are refused too.
  • A provider TeamRunner does not know (opnai/gpt-5) is refused with the nearest one; so is a teamrunner/ model other than teamrunner/demoLLM.
  • As with any model, plain validate and every run ask the provider whether it serves the model, and look for its key; validate --offline does not.

params:

The model's settings, one per line. The same list a member's params: takes: temperature, top_p, top_k, max_tokens, max_completion_tokens, seed, stop, presence_penalty, frequency_penalty, reasoning_effort, verbosity, thinking. Any other name is refused at its line, so a profile can never change where your key and your words are sent (api_base, api_key, mock_response are refused). New in 0.0.7.

params: that is not a block of name: value lines is refused.

Naming a profile

A profile is named by its file name, with .yaml, so it is never mistaken for a model: careful.yaml, not careful or models/careful.yaml.

  • default_model: careful.yaml in team.yaml: every member of the team that has no model: line.
  • model: careful.yaml in a member: that member, whatever the team's default.
  • Backups. A list may mix profiles and models, in order of preference: model: careful.yaml, openai/gpt-5. Each profile in it brings its own settings. Before the first turn, the member gets the first one available.
  • A profile that is not there is refused at the line that names it, with the nearest profile's name if one is close (carefull.yaml → did you mean careful.yaml?).

The member's own settings win, key by key. A member that names a profile and has params: of its own runs with the profile's settings, each replaced by the member's where both give one:

# models/careful.yaml          # critic.md
name: openai/gpt-6-luna        model: careful.yaml
params:                        params:
  reasoning_effort: high         max_tokens: 100
  max_tokens: 4000               temperature: 0.3

The critic runs with reasoning_effort: high (from the profile), max_tokens: 100 and temperature: 0.3 (its own). teamrunner show debate/critic prints this, with where each value came from.

Keys in the file

A profile is part of the team, so it is checked for API keys like every other file, and a key found in it is refused at its line. Keys live in ~/.teamrunner/.env.

Related files

  • team.yaml: default_model:, which may name a profile.
  • A member: model:, and its own params:, which override the profile's.
  • experiment.md: models/careful: file:variants/careful.yaml puts a whole profile in place for one condition.
  • A variant: the profile file a condition uses.
