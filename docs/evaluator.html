metrics/.md

An evaluator is a .md file in an experiment's metrics/ folder: a model that grades each run with a rubric you write. It is written like a member, settings on top and the rubric below, but it is never part of the team. It is never told which condition a run came from.

A first evaluator

How well did each side of a debate back its claims? Make metrics/evidence.md in the experiment's folder:

---
kind: evaluator
description: How well each side backed its claims
model: anthropic/claude-sonnet-5-5
params: {max_tokens: 600}
output:
  evidence: 0
  better: [advocate, critic]
  reason: ""
---
You are grading a debate on: {{inputs.topic}}

{{transcript}}

Score from 1 to 5 how well the speakers backed their claims with
evidence, say which side did it better, and give your reason in two
sentences.

and list it in experiment.md:

metrics:
  - metrics/evidence

When the runs are done, the evaluator reads each run's transcript and answers in three fields: a number, a choice and a text. The summary shows evidence.evidence as a mean per condition and evidence.better as the share of each answer; the reasons are in evaluations.csv when you export.

Try it, spending nothing:

teamrunner experiment advocate_model --plan # the cost of evaluating is its own line in the estimateteamrunner experiment advocate_model --rehearse # every run and every evaluation, with no model

The rest of this page is every setting in detail.

The settings block

The settings go at the top, between two lines of ---; the rubric is everything below. A file that does not start with --- is refused. A word the evaluator does not know is refused with the nearest known word, or the list of its settings: a member's tools:, or temperature: written outside params:, is refused.

Setting Needed What it is
kind yes evaluator
description no What it grades, for people
name no Its name in the summary; the file's name if left out
model yes The model that grades, as provider/name
params no The model's settings
output yes What it answers, and of what type
evaluations no How many times each run is graded (default 1)

kind:

kind: evaluator. Without it, or with another word, the file is refused: kind: is answer_key or evaluator. An evaluator is a .md file; kind: evaluator in a .yaml file is refused, as is kind: answer_key in a .md.

description:

Any text: what the evaluator grades. It is for people. It is not sent to the model, and editing it does not make a new version. New in 0.0.7.

name:

The evaluator's name, which starts each of its measures (evidence.better) and names the file its grades are kept in, evaluations/<name>.jsonl. Without it, the name is the file's name without its ending.

A name uses letters, digits, _ and -. Anything else is refused, and so is a file named with a dot or a space (evidence.v2.md) that has no name: line. New in 0.0.7. Two metrics in one experiment with the same name are refused.

model:

The model that grades, written provider/name: model: anthropic/claude-sonnet-5-5. An evaluator always names its own model; it never takes the team's, so model: is needed, and a model with no provider (gpt-5) or a team's profile (engineer.yaml) is refused.

Its key is needed, as a member's is, in ~/.teamrunner/.env. It is looked for when the evaluations start: without it nothing is evaluated, the message names the key to add, and the runs are kept to be evaluated next time. Under a cost ceiling, the model needs a list price, or nothing starts.

Choose a model that is not one of the team's when you can, so the grader is not grading its own words.

params:

The model's settings, as a member's params:: params: {max_tokens: 600}. Only the model settings list is taken: temperature, top_p, top_k, max_tokens, max_completion_tokens, seed, stop, presence_penalty, frequency_penalty, reasoning_effort, verbosity, thinking. Any other word is refused with the nearest (temprature → did you mean temperature?). New in 0.0.7.

max_tokens also sets how much of a reply the cost estimate and the ceiling set aside. If the model refuses a setting (temperature: 0 on a model that takes only 1), nothing is run, and the message is the model's own.

output:

What the evaluator answers, one field a line, written as a member's output:. The value you write gives the field's type:

You write The answer is The summary shows
score: 0 a number its mean, with a 95% interval
complete: false yes or no the share of yes, with the Wilson interval
better: [advocate, critic] one of these words the share of each answer
reason: "" text nothing: text is in evaluations.csv

output: is needed and must have a field. Text cannot be counted, so an evaluator whose answers are all text is allowed but adds nothing to the summary.

A reply that does not fit output: (a word for a number, a choice not on the list) is sent back to the model to answer again, up to three tries in all. If it never fits, that evaluation is not made, and it is tried again on the next command. New in 0.0.7.

evaluations:

How many times each run is graded, a whole number, 1 or more (default 1). Each is a fresh call. A run's value is then:

  • for a number, the mean of its grades;
  • for yes or no with more than one grade, the share of yes, shown as a number;
  • for a choice, the most common answer, or tie when two answers are equally common.

--export writes beside each run's value, in metrics.csv, how many grades it came from and how much they agree: the standard deviation, or for a choice the share giving the most common answer.

Raising evaluations: adds the grades still missing and keeps those made; it does not make a new version. New in 0.0.7. For a panel of graders, write several evaluator files.

The rubric

Everything below the second --- is the rubric: the instructions the model gets. Write it as you would a member's prompt. It is sent with its placeholders filled from one run, followed by "Give your evaluation now."

Placeholders

An evaluator reads only what its placeholders give it:

Placeholder Gives
{{transcript}} everything the members said, in order, each with its name
{{output}} the run's output.md
{{<member>.output.<field>}} that member's last answer in that field: {{emma.output.flagged_lines}}
{{inputs.<name>}} one of the run's inputs: {{inputs.topic}}

Spaces inside the braces do not matter ({{ transcript }}).

  • Any other placeholder is refused, {{condition}}, {{seed}} and {{everyone.output.…}} included: an evaluator reads only these four kinds.
  • A member or field must be one some condition has, and the field must be declared under that member's output:; a misspelled one is refused.
  • An input must be one a condition's team has; a typo is refused with the nearest ({{inputs.spek}} → did you mean {{inputs.spec}}?). New in 0.0.7.
  • It must see the run. A rubric with none of {{transcript}}, {{output}} or {{<member>.output.<field>}} is refused, since it would be sent only its own text.

When a run has nothing to fill a placeholder with, the model reads (none) for a member's answer or an input, (no output) for a missing output.md, and (nothing was said) for an empty transcript.

Blind grading

The evaluator is never told the condition, the factor levels, the seed, the replicate, the costs, the models or experiment.md, and every grade is a fresh call, so it cannot compare runs. Blinding removes the label, not the evidence: if one condition writes in a visibly different way, the transcript gives it away. Then grade a member's typed answer ({{judge.output.verdict}}) or {{output}} rather than the transcript.

When evaluations run

teamrunner experiment <name> makes the runs still to do, then evaluates. Each evaluator grades every run that counts and has no grade from its current version, in an order drawn from the experiment's seed and mixed across conditions, so no condition is graded all at once. Up to max_concurrent evaluations go at once.

Command Runs Evaluates
teamrunner experiment <name> the runs still to do grades still missing from the current version, except on runs an earlier version graded
teamrunner experiment <name> --evaluate none every run missing a grade from the current version, including runs graded by an earlier one
teamrunner experiment <name> --no-evaluate the runs still to do none
teamrunner experiment <name> --rehearse every run, with no model the rehearsal's runs, with no model, at no cost

Evaluating counts in the experiment's cost, and max_cost_usd: covers running and evaluating together. The estimate has its own line for evaluating, and counts the evaluations still owed from earlier sessions. New in 0.0.7. An evaluation that does not fit under the ceiling is not sent; it is made on the next command.

Each grade is kept as a line in the run's evaluations/<name>.jsonl, with the prompt sent, the reply, the cost and the evaluator's version. Lines are only added, never rewritten.

Versions

Every grade records the evaluator's version: its fingerprint. The version changes when you change the rubric, model:, params:, output: or name:. It does not change for description:, evaluations: or id:, or for comments and spacing in the settings.

When you change the version after runs were graded, nothing is spent on its own. The next teamrunner experiment <name> says so and what grading again would cost:

evidence.md changed since 20 runs were evaluated. To evaluate them again (≈ $0.42): --evaluate

--evaluate grades them with the new version. The old grades stay in the run's folder and in evaluations.csv, but the summary and metrics.csv use only the current version's; until a run is graded again, the summary leaves it out as "not evaluated by its current version". Grades made before 0.0.7 by the same file still count. New in 0.0.7.

An evaluator is never part of the study: editing it never stops the experiment or asks for --restart.
