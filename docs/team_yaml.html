team.yaml

team.yaml is the team's charter: it marks its folder as a team, says what the team does, names the model its members run on, and gives the inputs its prompts use. It is the only file a team must have.

A first team

Make a team in your workspace, then make its team.yaml read:

name: debate
description: Two debaters argue a topic; a judge decides

default_model: openai/gpt-6-luna

message_goes_to: topic

default_inputs:
  topic: "Remote work makes teams more productive"

Every member that names no model runs on openai/gpt-6-luna. Any prompt that writes {{topic}} gets the default topic, unless the run gives another one; --message fills topic.

Try it, spending nothing:

teamrunner new debate # the folder, a starter team.yaml, a .gitignoreteamrunner validate debate --offline # checks the files, with no network and no keyteamrunner explain debate # in plain words: members, inputs, who acts whenteamrunner run debate --rehearse # the whole flow, with no model, at no cost

A team needs members to do anything: see a member. In teamrunner ui, choose + Team, then select team.yaml on the left to edit it.

The rest of this page is every setting in detail.

The folder

A folder is a team when it holds team.yaml. Beside it:

debate/
├── team.yaml        the charter (this page)
├── advocate.md      a member: any .md file that starts with a settings block
├── critic.md
├── judge.md
├── chair.md         who acts when (optional)
├── models/          model profiles, one .yaml each (optional)
└── runs/            one folder per run, made on the first run
  • Members. Every .md file that starts with a --- line is a member. A .md file that does not (a README.md, notes) is ignored, and so are files of other kinds and folders without a team.yaml.
  • Reserved names. team.yaml, chair.md and manager.md are never members. models/, runs/ and tools/ at the top of the team are not searched for members.
  • No team.yaml at all: validate and run stop, saying the folder is not a team folder.

Not yet. manager.md, whiteboard.yaml, a tools/ folder of your own and a team inside a team (a subfolder with its own team.yaml) are refused: each "comes in a later version of TeamRunner". pathways.yaml and state.yaml are refused as no longer used.

The settings

team.yaml holds one name: value line per setting. JSON is read too. Every setting is optional.

A file that is not valid YAML is refused at the line where reading failed. A file that holds a list, or anything other than name: value lines, is refused. A file that is not UTF-8 text, or cannot be read, is refused with the line and how to fix it. New in 0.0.7. An empty file is a team with every default.

Any word the file does not know is refused with the nearest known word (default_modle → did you mean default_model?). Three old words say what to do instead: spec_version: (files carry no version line; delete it), defaults: (put model: on each member, or give the team default_model:) and channels: (who sees what comes in a later version; for now everyone reads everything said).

Setting Needed What it is
id written for you The team's permanent tag
parent_id written for you The id of the team this one was copied from
name no A short name; the folder's name if absent
description no One line: what the team does
default_model if a member names no model The model for every member that names none
message_goes_to no The input --message and --file fill
default_inputs if prompts use inputs Each input's value when a run gives none

id:

A 26-character tag, the same for the life of the team: it stays when you edit, rename or copy the folder, so runs of this team can be found across projects. You never write it. The first validate or run adds it above the first setting, with a comment saying what it is:

id: 01M7S3H4BZA445KXAA87TJXDHM  # added by teamrunner — keeps this team's history together

Wherever TeamRunner shows an id, it shows the last eight characters after a "…" (…87TJXDHM).

  • A team.yaml that opens with a --- line, as many editors write it, gets its id below that line. New in 0.0.7.
  • If the id cannot go into the file without breaking it (a team.yaml written as JSON, for example), the file is left exactly as it was and validate warns that it could not write an id. New in 0.0.7.
  • A value that is not a 26-character id is refused: delete the line, and TeamRunner writes a new one.

parent_id:

Written by teamrunner new <name> --from <team>: the copy gets a fresh id:, and parent_id: names the id it was copied from. Like id:, it must be a 26-character id, and you never write it.

name:

Any short text: name: debate. Without it, the team is called by its folder's name. It is shown at the top of validate, explain and every run, and it becomes part of each run folder's name (runs/2026-11-18_231357_debate).

  • An empty name (name: "") and a number (name: 42) are refused; quote a number to use it.
  • The name may hold any characters. In a run folder's name, everything but letters, digits, _ and - becomes _, and it is cut to 60 characters, so name: "my team: v2?" makes …_my_team_v2. New in 0.0.7.

description:

One line of text, for people: explain shows it beside the name. No model ever reads it. A number is refused; quote it.

teamrunner new my_team --describe "…" (or --describe-file brief.txt, or Describe it in the browser page) keeps the description the team was written from as comment lines at the top of team.yaml. New in 0.0.7.

default_model:

The model for every member of this team whose file has no model: line. A member's own model: always wins. Write one of:

  • A provider's model, as provider/name: openai/gpt-6-luna, anthropic/claude-sonnet-5-5, ollama/llama3.2. teamrunner/demoLLM is the free hosted demo.
  • A model profile in the team's models/ folder, by its file name with .yaml: default_model: careful.yaml. See a model profile.
  • Several, separated by commas, in order of preference: default_model: openai/gpt-6-luna, anthropic/claude-sonnet-5-5. Before the first turn TeamRunner gives each member the first one that is available, keeps it for the whole run, and says so when it is not the first. Profiles and provider models can be mixed.

What is refused, and why:

  • Not a model (default_model: gpt-5, with no provider): a model is written provider/name or as a profile ending in .yaml.
  • A provider TeamRunner does not know (opnai/gpt-5), with the nearest one suggested.
  • A teamrunner/ model other than teamrunner/demoLLM.
  • A profile that is not in models/, with the nearest profile's name if one is close.
  • The same model twice in one list.
  • No model anywhere: when there is no default_model:, every member without model: is refused with "has no model".

validate --offline checks only that the line is written right. Plain validate, and every run, also asks each provider whether it serves the model and looks for its key, before any turn.

message_goes_to:

The input that --message "<text>" and --file <path> fill, when you run the team: message_goes_to: topic. It lets the prompts keep a name that reads well.

  • It names one input, one word of letters, digits and underscores. An input no prompt uses is refused, with the nearest input's name (topc → did you mean topic?).
  • Without it, --message fills the input named message if a prompt uses one, or else the team's only input if it has exactly one.
  • If neither works (several inputs and no message_goes_to:), a run with --message stops before any turn, saying the team has nowhere to put it.
  • --message and --file cannot both be given. A task file (--task-file) gives inputs by name and does not need this line; giving the same input both ways stops the run.

default_inputs:

The value of each input when a run does not give one, one name: value line each. An input is a placeholder a member's prompt uses, such as {{topic}} (see the prompt).

default_inputs:
  topic: "Remote work makes teams more productive"
  audience: "a city council"
  • Names are one word: letters, digits and underscores. my-input: is refused.
  • Values are text (quote it: no and on stay words, but quoting is safest), a number, true/false, a list or a block of settings. A list or a block reaches the prompt written as JSON. A line with no value (extra:) is refused: an input with no default is left out.
  • An input no prompt uses is a warning, with the nearest used name.
  • An input a prompt uses with no default is a warning: every run must then give it, with --message, --file or --task-file. A run that does not stops before any tokens are spent, naming the input.
  • default_inputs: that is not a block of name: value lines (default_inputs: hello) is refused.

When a run starts, it says which inputs were given and which came from the defaults, and its record keeps the same.

A team whose prompts use no placeholders takes no inputs and needs no default_inputs:.

Keys in the files

A team is meant to be shared, so anything in its files that looks like an API key is refused at its line: keys live in ~/.teamrunner/.env. Every text file in the team is checked (.md, .yaml, .yml, .json, .txt, .csv, .tsv, .py, .toml, .ini, .cfg), except runs/ and hidden folders, and Brave, Groq and xAI keys are recognised as well as the others. New in 0.0.7.

Related files

  • A member: the files that do the work, and where {{inputs}} are used.
  • A model profile: what default_model: careful.yaml names.
  • chair.md: who acts when; without it, members act in filename order.
  • A toolkeeper: the member who holds a tool.
  • experiment.md: runs versions of this team side by side, with task: in place of default_inputs:.
  • A task: several inputs in one file, for --task-file.
