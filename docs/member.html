A member (<name>.md)

A member is one Markdown file in a team's folder: settings at the top, between two --- lines, and the member's instructions, its prompt, below them. Its name is the file's name. This page is about members that think with a model (kind: llm, the default); a member that holds a tool is a toolkeeper.

A first member

In a team's folder, make judge.md:

---
description: Decides who argued better
output:
  winner: [advocate, critic]
  reasoning: ""
---
You have watched a debate on:

{{topic}}

Decide which side argued better. Announce the winner and explain
your decision in one paragraph.

The member is called judge, after its file. It names no model, so it runs on the team's default_model:. {{topic}} is filled with the team's input topic before the judge's turn. Besides its words, the judge answers two typed fields: winner, one of advocate or critic, and reasoning, text.

Try it, spending nothing:

teamrunner validate debate --offline # checks every file, with no network and no keyteamrunner show debate/judge # the judge as it will run: model, settings, and where each came fromteamrunner run debate --rehearse # no model: placeholder words, a random winner, at no cost

In teamrunner ui, select the team, choose + Member, paste the file and Save; As it will run shows the prompt with its inputs filled in.

The rest of this page is every detail.

The member's name

A member's name is its file name, without .md and without any digits and underscores at its start: judge.md and 03_judge.md are both judge. There is no name: setting; a name: line is refused, saying to rename the file instead. The flow, access: lists and messages all call the member by this name.

  • Names are letters, digits and underscores, and start with a letter once the prefix is taken off. my-judge.md, 01-judge.md (its name would be -judge) and 007.md (no name left) are refused: rename the file.
  • Capitals count: Judge.md is the member Judge, not judge.
  • Two files may not give one name: judge.md and 01_judge.md together are refused.
  • Reserved names. done, stop, others, everyone, standard and deny are words the flow and the access lists use, so no member may have them. chair.md and manager.md are not members at all.
  • The order. With no chair.md, members act one turn each in the order of their file names, which is why a numeric prefix is useful: 01_host.md, 02_guest.md. The names are compared character by character, so capitals come before small letters, and 10_x comes before 2_y; give every prefix the same number of digits. Toolkeepers take no turn of their own.

Which files are members. Every .md file in the team's folder that starts with a --- line. A .md file that does not start that way (a README.md, notes) is ignored. A settings block that is never closed by a second --- line is refused. A file that is not UTF-8 text, or cannot be read, is refused with the line and how to fix it, and a file saved by Windows Notepad, with its invisible mark at the start, is read as written. New in 0.0.7.

The settings block

The settings are YAML, one name: value per line. All are optional; an empty block (--- then ---) is a member with every default, as long as the team has a default_model:.

Any word the block does not know is refused with the nearest known word (descripton → did you mean description?).

Setting Needed What it is
id written for you The member's permanent tag
parent_id written for you The id of the file this one was copied from
description no One line about the member, for people
kind no llm (the default) or toolkeeper
model if the team has no default_model: The model it runs on
params no Model settings, such as temperature
output no Typed fields it answers besides its words

tools:, access: and others: belong to toolkeepers only; on any other member each is refused, saying to give the tool to a toolkeeper and let this member ask it. See a toolkeeper.

Not yet. reads:, writes:, rules:, lines:, kind: rules, kind: human and kind: announcer are refused: each "comes in a later version of TeamRunner".

id:

A 26-character tag, the same for the life of the member: it stays when you edit the prompt, rename the file or copy it to another team. You never write it. The first validate or run adds it as the block's first setting:

id: 01M7S3H4C3F1NQJNY2E9X9QM8B  # added by teamrunner — keeps this agent's history together

TeamRunner shows it as its last eight characters, …E9X9QM8B, often beside the name: judge (…E9X9QM8B). Each run keeps a fingerprint of every member's file, so an edited prompt is a new version of the same member, with nothing for you to write. A value that is not a 26-character id is refused: delete the line, and TeamRunner writes a new one. If you copy a file by hand, delete its id: line so the copy gets its own.

parent_id:

Written by teamrunner new <name> --from <team>: every copied file gets a fresh id:, and parent_id: names the id it had. It must be a 26-character id, and you never write it.

description:

One line, for people: explain and show show it beside the member's name. It is not sent to the model; what the model should know goes in the prompt. A number is refused; quote it.

kind:

llm, the default, is a member that thinks with a model; leaving the line out means the same. toolkeeper is a member with no model that holds one tool: see a toolkeeper.

  • Any other word is refused, saying the choices are llm or toolkeeper.
  • kind: gate is refused as renamed: write kind: toolkeeper.
  • A list or a block (kind: [llm]) is refused: kind: is one word. New in 0.0.7.

model:

The model this member runs on. Without it, the member runs on the team's default_model:; with it, its own line wins. It is written the same way:

  • A provider's model, provider/name: model: anthropic/claude-sonnet-5-5, model: ollama/llama3.2, or teamrunner/demoLLM for the free hosted demo.
  • A model profile in the team's models/, by its file name with .yaml: model: careful.yaml. See a model profile.
  • Several, separated by commas, in order of preference: model: careful.yaml, openai/gpt-5. Before the first turn the member is given the first one available and keeps it for the whole run; each run says so when it is not the first, and records it.

Refused: a model with no provider (gpt-5), a provider TeamRunner does not know (with the nearest suggested), a teamrunner/ model other than teamrunner/demoLLM, a profile that is not in models/, the same model twice in one list, and model: with nothing after it. With no model: and no default_model:, the member is refused as having no model.

validate --offline checks only that the line is written right. Plain validate, and every run, also ask each provider whether it serves the model and look for its key, before any turn. A model is never swapped for another silently: only the backups you list are tried.

teamrunner show <team>/<member> prints the model and settings the member will run with, each marked with where it came from.

params:

Settings for the model, one per line:

params:
  temperature: 0.2
  max_tokens: 2000

Only these are taken: temperature, top_p, top_k, max_tokens, max_completion_tokens, seed, stop, presence_penalty, frequency_penalty, reasoning_effort, verbosity, thinking. Any other name is refused at its line, with the nearest allowed word (temprature → did you mean temperature?). They shape the reply and nothing else, so a team someone else wrote can never change where your key and your words are sent. New in 0.0.7. This means a setting a provider takes that is not on the list, such as Ollama's num_ctx, is refused too. New in 0.0.7.

  • params: that is not a block of name: value lines (params: 0.2) is refused.
  • With a profile, the profile's params: come first and the member's own replace them key by key: a profile with max_tokens: 4000 and a member with max_tokens: 100 runs with 100, and keeps every other setting of the profile.
  • TeamRunner passes the values as written; whether a model accepts a setting is up to its provider.

output:

Typed fields the member answers besides its words. They are the only part of a reply that the flow's decisions and an experiment's metrics may read: TeamRunner never searches free text for words.

output:
  winner: [advocate, critic]   # a choice between these
  reasoning: ""                # text
  score: 0                     # a number
  sure: false                  # true or false

Each field is a name (letters, digits and underscores) and one of:

You write The field is
a list of two or more words, [pass, fail] a choice: one of them
"" or any text text
a number, 0 a number
true or false a flag: true or false
{type: choice, options: [pass, fail]} the long form; type: is choice, text, number or flag
  • Choices are words of letters, digits and underscores, all different. A list of one, a repeated option, or an option with a space is refused. Numbers as options ([1, 2]) are refused; quote them: ["1", "2"]. yes and no are read as words.
  • The long form takes type:, options: (for a choice, and only for a choice) and description:, a note for people that is not sent to the model. Any other word in it is refused.
  • output: {} is refused; leave the line out for a member that answers in words only.

The model is asked to answer in that shape. A reply that does not fit is sent back with what was wrong, up to three tries in all; if the third does not fit, the run ends there as failed. In a rehearsal, each field is given a value at random from what it allows (a random option of a choice), so decisions in the flow really happen.

A member whose output: field has labelled arrows in chair.md is making a decision: see chair.md. A field is measured in an experiment by its path, judge.output.winner: see experiment.md.

The prompt

Everything below the second --- is the member's prompt: the instructions its model is given at every turn, as written, with each input filled in. Its description: is not sent with it, so say in the prompt who the member is and what to do. What others have said reaches it separately, as the conversation so far.

A member with no prompt, or with only the starter line that + Member writes ("Write this member’s instructions here."), stops a real run before any model is called, naming the member. A rehearsal still runs, since it calls no model. New in 0.0.7.

Inputs

{{topic}} in a prompt is an input of the team: the run fills it from --message, --file, a task file or the team's default_inputs:. Spaces inside the braces do not matter: {{ topic }} is topic. The same input may appear in any number of members' prompts, and each gets the same value.

  • Input names are letters, digits and underscores: {{my input}} is refused.
  • An input with no default is a warning, since every run must then give it; a run that does not stops before any tokens are spent, naming it.
  • Text is filled in as written; a number, a list or a block of settings as JSON.
  • {{whiteboard.<item>}} is refused: reading the whiteboard "comes in a later version of TeamRunner".
